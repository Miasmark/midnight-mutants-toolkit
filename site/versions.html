Nothing about the game changed

Before the differences, the sameness — because it is almost total.

  • Banks 1, 2 and 4 are byte-identical. Every character set and all 39 terrain slices: the whole of the artwork rooms are built from.
  • All 76 area headers are byte-identical. Every room's graphics page, darkness, map limit, exits on four edges, item, spawn budgets and slice list.
  • Every gameplay constant matches once read at its relocated address — toughness seeds, weapon fire rates, the diamond and ghost effects on maximum health, contact damage, the creature-kind table, spawn amounts and rates, all three boss records and the victory reward, the terrain property tables.

So the two play the same. What differs is display timing and colour, which is what a PAL conversion is.

The screen is taller

PAL gives 312 scanlines against NTSC's 262, and the conversion spends them in the display list.

All of the added height goes to the top border, above the playfield, so the ten bands of a room are untouched. The message screen's display list gets the same treatment, and three more entries are added in bank 7.

Which is why almost everything moved

Those inserted entries sit in the middle of a bank, so everything after them slides along.

bankshiftcause
6+3 from $42B7 one extra display-list entry
7+9 across $D200–$D600 three more entries

Bank 6 is the clean case to measure. Of its 14,720 differing bytes, 564 are relocation fixups — an address operand adjusted by exactly three — and only 19 bytes are genuinely different: one loop bound in the display-list copier, and a run of palette values.

The jump table at the head of the bank shows it plainly. Every target moves three bytes: JMP $4A2A becomes JMP $4A2D.

And it was done by eye, not by rule

Auditing the block of eight palettes that is live during play, the shift is selective. Hue 1 is remapped twice and left alone four times; hue 2 is remapped three times and left alone three.

The giveaway is the byte $24: kept as $24 in one palette and moved to $34 in another. The same value, treated differently depending on where it sits — so each palette was judged on a PAL set rather than run through a formula.

Visible on the first screen

The heart draws from palette 4: $1A $22 $0D on NTSC and $1A $32 $0D in Europe. Only the body colour moves, hue 2 to hue 3, and it reads noticeably pinker. That palette is shared by the crypt key, necklace, knife, axe, blaster and mega blaster, so all of them shift with it.

The music was never retimed

Which is the one difference you can hear.

The duration and instrument tables are byte-identical, and the song table differs only by two relocated pointer bytes. A note's duration is a count of frames and the engine ticks once per frame, so tempo follows the machine.

NTSCEurope
refresh59.96 Hz49.92 Hz
a 16-frame note267 ms321 ms

Everything plays at 83.3% speed — a sixth slower, uncompensated. The editor can correct it, either by rescaling the sixteen duration entries or by a 16-byte shim that runs one extra music tick every fifth frame (18 bytes with the two that repoint the vector at it).

The signature block is gone

And the header metadata differs, in ways that say who dumped it rather than what the cartridge is.

$FF80–$FFF8 holds 121 bytes of high-entropy data in the NTSC image and is filled with $FF in the European one. No code references it — the only references into that page anywhere in the listings are the reset and IRQ vectors, which are identical in both. That is consistent with the console signature block, which the European image does not carry.

The .a78 header differs in seven bytes: the title text, the TV-type flag, and the cart-type flags. The NTSC header declares bank 6 mapped at $4000 and the European one does not, though the code is laid out the same way — which looked like less careful curator metadata rather than a difference in the cartridge.

Since confirmed

It was exactly that. Trebor's PAL release carries the same cartridge data — 0 differing bytes in all 131,072, CRC32 7CA6D521 either way — with the cart type corrected from $0002 to $0012, adding the bank6@$4000 bit; their changelog lists it as a deliberate fix. The NTSC pair differ only in header version and two v4 bytes.

MAME loads both through the same a78_sg handler and they are indistinguishable in play — same RAM hash, same frame — but an emulator or flash cart that honours the header may not be. It is also why this project's patches now exclude the header, so one patch fits either file.

Both are fully supported

One address map covers the whole difference, so every tool in the project works on either.

A cartridge is identified by reading three constants that sit after a seam at both candidate addresses; whichever placement reads the expected bytes names the release. Checked against 22 landmarks, every hardcoded table and gate lands on identical bytes once mapped.
